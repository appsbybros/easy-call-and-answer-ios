Owner handoff

From GitHub to TestFlight.

The source repository is ready for simulator verification. No signed upload has been made and no Apple secrets are configured in this new repository.

1. Apple setup

  1. Register the explicit App ID com.appsbybros.easycall in your Apple developer account. Create its App Store Connect app record.
  2. Create the non-consumable com.appsbybros.easycall.lifetime, add a price and localization, and provide the review screenshot when submitting the purchase. Suggested U.S. price: $9.99, a proposal rather than a configured price.
  3. Export an Apple Distribution certificate together with its private key as a password-protected .p12, and create an App Store provisioning profile specifically for this App ID.
  4. Use an App Store Connect Team API key with a role that permits uploading builds for this app.

2. Repository secrets

In GitHub → Settings → Secrets and variables → Actions, add these repository secrets. Never commit the files or paste their content into issue comments.

SecretValue
ASC_KEY_IDThe Team API Key ID
ASC_ISSUER_IDThe Team API issuer UUID
ASC_PRIVATE_KEYEntire .p8 private-key text
DISTRIBUTION_P12_BASE64Base64 of your Apple Distribution .p12
DISTRIBUTION_P12_PASSWORDThat .p12's password
PROVISION_PROFILE_BASE64Base64 of the App Store .mobileprovision file for this app

This workflow uses explicit distribution signing rather than assuming a fresh runner has an Xcode account or can obtain cloud signing. The team is read from the profile's TeamIdentifier, not inferred from its App ID prefix. It validates app identity, expiry and the matching private certificate before compiling. Signing files are removed at the end.

3. Run

  1. Wait for Build, test and capture iOS to pass on the commit you intend to upload.
  2. Run TestFlight upload. Enter a new build number above the last accepted build (1 for the first upload). It checks the same commit's verification result first.
  3. After upload, check Apple processing and any rejection message. A successful upload command alone does not mean processing passed.
  4. Add internal testers in App Store Connect, then install through TestFlight.

4. Physical iPhone release checks

  • With a consenting tester, start a normal call, answer it on Apple's call UI, and end it there. Check locked and unlocked screens, dual SIM if used, interrupted/declined calls and repeated taps.
  • Try Bluetooth and speaker routing with the actual accessories, while stationary. Simulators cannot prove those paths.
  • Import a selected contact with multiple numbers and a photo. Check that no other contacts appear in Easy Call.
  • Schedule a notification, then test tapping it while the app is open, backgrounded and terminated. Cancel it and remove the contact.
  • Test VoiceOver, maximum text size, landscape and iPad. Verify all critical controls remain reachable by scrolling.
  • Test the real sandbox purchase, cancellation, pending approval, restore and refund. No tester should be charged through TestFlight.

5. Store submission

Use the app-store/en-US and app-store/he text files and verified simulator screenshots. Host this support page and privacy.html publicly, then enter the actual URLs; these files have not been published to your existing website. Confirm business contact details, prices, questionnaire answers and first-IAP review information before submitting.
