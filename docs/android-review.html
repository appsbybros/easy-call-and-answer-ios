Source audit · 8 October 2026

Make the call controls
the dependable part.

The Android app has valuable ideas: familiar contacts, large targets, caller announcements, speaker options and trusted-person shortcuts. Its risk comes from many interacting layers around a time-sensitive call: global incoming/outgoing/waiting state, voice helpers, analytics, custom ringing, overlays, settings and conference handling.

Evidence limit: the intermittent customer calls were not reproduced on a carrier/OEM device. The findings below identify concrete code paths capable of producing the symptoms; they do not establish which path affected each customer. Existing uncommitted fixes were present before this task and were preserved.

Validation performed

Nine existing CallActionsTest tests passed in an isolated Android/Robolectric harness using byte-for-byte copies of the current adapter and tests. Cases cover missing references, ambiguity, stale screens, rejecting a ringing call, conference parents, exceptions and retry, removed calls, disconnecting retry, and refusing to answer an already active call.

The full :app:testStandardDebugUnitTest task fails before tests because ../lockscreenlib and ../referralslib are absent. No substitute production libraries were fabricated, no current Android source was overwritten, and no real calls were placed. The isolated test pass is not a claim that the full app or OEM radio behavior passes.

How I would simplify Android safely

  1. One main-thread call registry keyed by actual Telecom Call objects, one command adapter, and state derived from callbacks. Make ringing/active/held/disconnected explicit; never use a success-looking flag as confirmation.
  2. Always-visible Answer/Decline/End with at least 64dp targets, text labels and accessible feedback. Keep controls usable while a request is pending; allow a controlled retry after a visible timeout.
  3. Separate contact/history UI from call control. An optional feature failure must not stop Answer or End.
  4. Keep favorites, keypad, recent calls, speaker/mute and useful caller announcements. Put voice answering, automatic routing, waiting/conference options and trusted-number restrictions behind a clearly explained advanced section.
  5. Remove automatic hangup from view lifecycle and generic error handling. Reduce custom lock-screen/ringtone manipulation where Android's supported call notification can do the job.
  6. Instrument anonymized request-to-state timing only with appropriate consent: action, call state, elapsed time, app version and device model. Do not record numbers or contact names. Test delayed/ignored requests, process recreation, lock screen, two SIMs, waiting/conference and Bluetooth routing with consenting test calls.

What iOS deliberately changes

The iPhone app uses Apple-controlled carrier calling and does not recreate those fragile Android Answer/End paths. It retains the clearer value—favorite people, large readable controls, notes and reminders—and explains Apple's own accessibility and Bluetooth features. It is not a general replacement for the iPhone's incoming cellular call screen.
